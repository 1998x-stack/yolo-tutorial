DATA / LABELS ／ CHAPTER 23

数据标注与格式：坐标契约与质量验证

标注是检测模型的监督信号本身。本章把不同格式的坐标约定、格式转换的边界情况、数据集划分与质量验证写成可复核的检查流程。

1. 标注就是监督信号本身

检测模型的训练目标由标注直接定义：分类头学习的是标注给出的类别，回归头学习的是标注给出的框。标注里的系统性偏差会被模型当成“正确的答案”学下来，换更深的网络或更久的训练都不会自动消失。因此数据工作不是训练的“前期准备”，而是模型上限的一部分。

标注错误有几种典型形态，它们对模型的影响各不相同：漏标把真实目标当背景，会提高漏检；错类把类别迁到别的语义上，专门拉低分类精度；坐标偏移（例如把左上角当成中心点写入）则同时破坏回归与匹配过程，因为在训练分配阶段，错位的框会与真实位置不匹配，甚至让正负样本被错误划分。

检测标注的难点在于它不是单一选择题，而是“在哪里 + 是什么”的联合判定。后文的三类格式只是同一信息的不同编码；理解编码差异，是避免转换错误的前提。

2. 三种格式，三种坐标契约

检测数据集的主流编码有三种。它们记录的是同一个矩形，但用不同的参数描述，并各自以不同的归一化约定存储，所以“拿到一个框”时必须先问清楚它属于哪种约定。

YOLO TXT：每张图像对应一个同名 .txt，每行一个目标，字段为 class_id cx cy w h，其中 center 与宽高都除以图像宽高，取值在 0~1。类别 id 从 0 开始并与训练配置中的类别顺序一致。COCO JSON：所有图像与标注集中在一个 JSON 中，bbox 为 [x, y, w, h]，是左上角加尺寸的绝对像素，另有 area 与 iscrowd 等字段。Pascal VOC XML：每张图像一个 XML，用 xmin, ymin, xmax, ymax 记录框的左右上下边界。

从 VOC/COCO 的绝对像素到 YOLO 的归一化值，换算关系为：

cx=x+w/2W,cy=y+h/2H,nw=wW,nh=hH

其中 W、H 为原图像素宽高。逆变换把归一化值乘回像素尺寸即可。最容易出错的不是公式本身，而是把 COCO 的中心点当成左上角，或忘掉除以图像宽高。

3. 格式转换：错误成堆的地方

转换脚本的核心往往只有几行算术，但边界情况很多，下面这些必须显式处理：

  • 类别映射：COCO 的 category_id 不一定从 0 开始也不一定连续，必须先建立一个固定、可记录的映射表（如按 categories 列表顺序），并写入训练配置。只靠字典 enumerate 顺序而不记录，重跑时可能得到不同的 id。
  • 裁剪与越界：目标可能部分超出图像，转换后宽高会大于 1 或坐标为负。要不要裁剪、还是保留并让数据加载器处理，必须在管线中统一约定，不能各部分各自行事。
  • 空图像：没有目标的图像应保留一个空的标注文件（背景样本），而不是省略文件，否则数据加载器可能将“图像存在但无标签”当作错误。
  • 退化框：宽或高为 0、或面积过小的框通常是无意义的，应在转换时过滤并计数，而不是留给训练器。
  • crowd / 分割字段：COCO 的 iscrowd 与 segmentation 在纯框检测中常被忽略，但若评测仍按 COCO 协议计算，这些语义会影响指标，需要与评测口径一并确认。

下面是一段只做坐标换算与裁剪的教学代码，用固定的一张 640×480 图像演示：

def coco_bbox_to_yolo(bbox, img_w, img_h):
    x, y, w, h = bbox           # COCO: 左上角 + 尺寸（绝对像素）
    # 夹紧到图像范围内，避免负坐标或超界
    x1 = max(0.0, min(x, img_w)); y1 = max(0.0, min(y, img_h))
    x2 = max(0.0, min(x + w, img_w)); y2 = max(0.0, min(y + h, img_h))
    if x2 <= x1 or y2 <= y1:
        return None             # 退化框，应过滤并计数
    cx = (x1 + (x2 - x1) / 2) / img_w
    cy = (y1 + (y2 - y1) / 2) / img_h
    return cx, cy, (x2 - x1) / img_w, (y2 - y1) / img_h

转换完成后，应用同一批输入同时跑通原格式与目标格式的加载器，并在可视化中叠加还原后的框，确认中心与尺寸没有发生镜像或偏移。

4. 组织与划分：先切数据，再做增强

YOLO 系列工具链默认采用图像目录与标签目录镜像的布局：images/train 对应 labels/train，文件名相同、扩展名不同，另有一个数据集配置文件描述根目录、各划分路径与类别名列表。图像与标签必须成对出现，命名不一致会导致加载时找不到监督。

划分上要在两个层面做约束。第一是不泄漏：连续视频帧、同一场景的多张照片、或同一张原图的切片必须整体归入同一个划分，否则验证指标会因为近重复样本而虚高。第二是保持分布：类别比例、目标尺度分布与场景类型在各划分中应尽量接近，否则验证集不能代表部署分布。

顺序也很关键：划分应在任何增强之前完成。若先做随机裁剪、拼接或切片再划分，同一原图的不同增广副本可能落到训练集与验证集两侧，形成隐式泄漏。

5. 质量验证：把“看起来对”变成“检查过”

标注质量需要在训练前用程序化检查拦下来，而不是靠训练曲线反推。最低限度的一组检查是：每个标签文件都有同名图像；每行字段数为 5；类别 id 在合法范围内；宽高为正；归一化坐标在约定范围内；换算回像素后框的面积不为零。对失败项应输出文件名与行号，便于回溯。

除了逐框校验，还需要统计整体分布：类别频率、目标尺度分布（面积或宽高）、宽高比分布、每图框数。这些分布直接决定后续的锚框或先验选择，也能暴露“某类只在少数图像里”这类隐式不平衡。

多人标注时，质量的核心是一致性。常用做法是让多名标注员先标同一批样本，用两两框交并比（IoU）度量分歧：

IoU=A∩BA∪B

对比阈值应提前约定（例如低于该值就进入复审）。分歧集中的样本与类别需要更新标注规范并重标，而不是仅取平均或多数投票了事。一刀切地把不一致的框丢弃，会系统性删掉本来就难得的难例。

固定图像 640×480、归一化宽高 0.10×0.15。拖动归一化中心横坐标 cx，查看同一框在 YOLO、COCO 与 VOC 三种约定下的数值（教学示意）。

6. 一手来源与复核边界

  1. COCO 数据格式说明：核对 bbox、area、iscrowd 与 categories 字段定义。
  2. Microsoft COCO 原论文（ECCV 2014）：核对标注与类别组织的原始描述。
  3. COCOeval 参考实现：核对面积分组与 IoU 匹配的实际计算口径。
  4. Pascal VOC 数据集主页与 devkit：核对 XML 标注中 bndbox 与 difficult 字段。
  5. Ultralytics 数据集文档：核对图像/标签目录镜像与数据集配置文件的字段。

本文的坐标换算与交互计算是确定性教学示例；其中的图像尺寸与归一化宽高为演示参数，不代表任何具体数据集分布。标注质量控制阈值需根据任务自行测定与记录。
