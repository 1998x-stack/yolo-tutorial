IMPLEMENTATION / TRAINING ／ CHAPTER 15

YOLOv5：从模型配置到可复现的训练、评估与导出

以 Ultralytics YOLOv5 v7.0 的经典 anchor-based 检测版为固定对象，解释 C3/SPPF/PAN-style、Detect 解码、AutoAnchor、数据 YAML、训练与独立验证，并提供数据标签审计器。

1. 首先指定版本：YOLOv5 不是一个永远固定的网络

YOLOv5 由 Ultralytics 团队在 2020 年起以开源实现的形式持续迭代，不是 YOLOv1–v3 原作者 Redmon 论文系列的又一篇同作者论文。在科研复核中，描述 YOLOv5 的核心证据应优先指向具体 Git tag、YAML 配置与训练/推理源码，而不是假定存在一个唯一的“YOLOv5 2020 原始论文”。

本文固定观察对象为 Ultralytics/yolov5 v7.0 的目标检测路径（该版本于 2022 年 11 月发布，仓库还支持其他任务）。此版的常见 YOLOv5s 基于 C3/部分 CSP 结构、SPPF 和 PAN-style Neck，使用经典 anchor-based Detect Head。后来 Ultralytics 软件生态中还出现了 YOLOv5u 这种 anchor-free 解耦 Head 变体，不能把新变体的训练损失和输出形状套到 v7.0。

2. 读懂 Detect Head：输出张量与坐标解码

经典 YOLOv5 的 anchor-based Head 对每个检测尺度输出一组按网格、anchor 和通道排列的预测。若一张图有 C=2 类，每个网格有 A=3 个锚框，那么预测通道数 A×(5+C)=21。在 640×640 输入下，各尺度候选数分别为 80²×3=19200、40²×3=4800、20²×3=1200，合计 25,200 个原始候选。它们不是最终的 25,200 次检测，仍需要分数筛选与 NMS。

N=3(802+402+202)=25200

与原始 YOLOv3 sigmoid(tx)+grid、exp(tw)×anchor 的写法相比，v7.0 YOLOv5 的经典推理解码使用扩展中心偏移及平方化宽高：

bxy=(2σ(txy)−0.5+g)×stride bwh=(2σ(twh))2×anchor

式中 g 是二维网格索引，stride 是输入像素相对于特征图单元的步长，anchor 在此必须使用与最终输出一致的像素单位。训练中的内部参数化、自动锚框校正和推理时的网格偏置应以对应 v7.0 models/yolo.py 为准。对来自较新 anchor-free YOLOv5u 的权重，不能套用这个解码器。

# 本仓库只计算经典 v7.0 的几何解码与候选数
python -m labs.yolov5_contract
# 输入 logit=(0,0,0,0)、grid=(4,6)、stride=32、anchor=(116,90)
# 解码中心=(144,208)，宽高=(116,90) 像素
# 这不是完整 YOLOv5 前向、训练或 NMS。

形状与解码契约提供了一组确定性边界检查，不会加载 PyTorch 或第三方模型权重。

3. 数据集：YAML 只是索引，真正的监督在每个 .txt 文件

YOLOv5 常用的检测数据结构包含 images/train、images/val 与对应的 labels/train、labels/val。每个文本标签行写成 class_id cx cy w h，坐标按图像宽高归一化，类别编号从 0 开始。如果只有两类，所有 class_id 只能是 0 或 1，且必须让 YAML 中的 names 与标注顺序完全一致。

# data/parts.yaml（请使用真实、已授权的数据路径）
path: /absolute/path/to/parts-dataset
train: images/train
val: images/val
nc: 2
names: [bolt, nut]

# labels/train/example.txt
0 0.5 0.5 0.25 0.3
1 0.2 0.7 0.1 0.15

上面的两个框都满足 0<w,h≤1 且 x±w/2, y±h/2 在 [0,1] 内。然而，“语法合法”仍不代表真实标注正确；必须把框画回原图核对物体，审查无标注负样本是否真的没有目标，并按视频/拍摄批次进行防泄漏划分。

# 无第三方依赖：审计本地标签目录，不需要加载图像
python -m labs.yolov5_contract --labels /path/to/labels/train --classes 2
# 报告：检查文件数、有效对象数和非法行详细位置
# 本脚本不读取 dataset.yaml，不能代替完整数据集/图像交叉检查。

可复现训练还需要保存数据划分清单、类名映射、采集场景和数据版本，不应只记录一个可变的路径名。

4. 用固定的 YOLOv5 v7.0 源码运行训练

YOLOv5 v7.0 的检测任务通常通过根目录的 train.py、val.py、detect.py、export.py 脚本运行。以下是一个准备和调用示例，不是本仓库已执行的训练；机器必须安装与 CUDA/CPU 环境兼容的 PyTorch、其余依赖、合法数据集与可获得的权重。

git clone --branch v7.0 --depth 1 https://github.com/ultralytics/yolov5.git
cd yolov5
python -m pip install -r requirements.txt

# 从 COCO 预训练的 YOLOv5s 检测权重开始微调；权重会按原仓库逻辑下载
python train.py --imgsz 640 --batch-size 16 --epochs 100 \
  --data /absolute/path/to/parts.yaml --weights yolov5s.pt \
  --project runs/train --name parts-v7-baseline

# 训练后的独立验证。此处的 val 不是外部测试集！
python val.py --weights runs/train/parts-v7-baseline/weights/best.pt \
  --data /absolute/path/to/parts.yaml --imgsz 640

# 在一张真实图像上推理，保存框与分数
python detect.py --weights runs/train/parts-v7-baseline/weights/best.pt \
  --source /absolute/path/to/demo.jpg --imgsz 640

正式项目应进一步锁定 Git commit、Python 和 PyTorch 版本、CUDA、随机种子、精度模式、训练/验证划分、超参文件、模型 YAML、类别表和权重哈希。训练输出目录不应由每次自动自增名称隐式决定，建议明确给出 project/name 并记录日志。若训练目标是可解释的技术审计，先用小样本检查标签、批次构造和 loss 是否合理，随后再花长时间完整训练。

5. AutoAnchor 与部署导出：别跳过中间的版本契约

经典 YOLOv5 使用锚框集合，对目标宽高先验的覆盖度有要求。AutoAnchor 是训练侧检查/优化先验的流程，可能计算最佳匹配的召回覆盖度并在不合理时建议或更新参考框。但它不是每次 inference 动态重新计算 anchors，也不保证“重新聚类就提升 AP”。检查聚类结果还需结合三检测尺度的正样本分布和统一的验证指标。

部署到 ONNX 时，v7.0 提供 export.py 的导出接口，仍需检查推理输出究竟是解码前的原始张量、解码后的候选，还是包含 NMS 的端到端结果。不同 --include、算子集、部署后端可能影响格式，不能仅因为文件扩展名是 .onnx 就假设输出可直接画框。

python export.py --weights runs/train/parts-v7-baseline/weights/best.pt \
  --include onnx --imgsz 640

# 推理验收至少比较几张确定性图片的框坐标/分数：
# PyTorch reference vs ONNX Runtime with identical letterbox and NMS
# 测量端到端延迟时明确是否包含前后处理。

6. 该怎样比较 YOLOv5n/s/m/l/x

这些模型配置通常由深度、宽度乘子控制网络规模，形成不同的参数与计算成本档位。但论文或 README 的某一张表里的 AP、速度或精度可能来自不同输入尺寸、测试时增强和不同 GPU。任何“s 比 n 快多少、m 比 s 高几个 AP”的结论都应该附数据集、模型 tag、设备、输入尺寸、batch、精度、是否包含后处理和统计方法。

检查维度必须固定或报告的条件
架构YOLOv5 v7.0 的具体 YAML、n/s/m/l/x 档、检测而非分割 Head
数据数据集版本、train/val/test、类别数量、图像分辨率
指标COCO AP50:95 与 AP50 区分，区分单图 latency 与 FPS
部署PyTorch/ONNX/TensorRT 后端、FP32/FP16、设备、NMS 时延

不要把 YOLOv5 v7.0 的经典 anchor-based Head 与较新的 Ultralytics YOLOv5u 无锚框版本混用：同名模型系列可以共享部分 Backbone，但训练监督和坐标解码并不相同。工程上最稳妥的方式是把“模型版本”当成完整的软件构建标识，而不是仅记录一个网络名字。
