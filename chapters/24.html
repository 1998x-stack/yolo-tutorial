TRAINING / PIPELINE ／ CHAPTER 24

训练流水线搭建：配置、循环与可复现

训练流水线不是一行命令，而是一组必须被固定和记录的约定：配置分层、有效批大小、学习率调度、验证节奏与检查点策略。

1. 流水线的第一目标不是快，而是可复现

训练检测模型时，同一份代码在不同时间、不同机器上跑出不同结果，往往不是玄学，而是某些变量没有被固定：库版本、数据划分、随机种子、数据加载顺序、是否用过预训练权重、学习率调度。可复现的含义是：给出同一份代码、同一份数据、同一个随机种子与同一套硬件环境，能得到在数值容差内一致的结果。

因此在写第一行训练命令之前，先把这些变量显式化：把模型结构、数据集、超参数分成可版本化的配置文件；记录代码仓库的 commit 与依赖版本；把数据划分固化为文件清单而不是每次重新随机；把随机种子、是否 AMP、是否 EMA 写进实验记录。一个“无法被重新跑出来”的指标，无论多高都没有工程价值。

2. 配置分层：把“决定”与“代码”分开

一个工程化的检测训练项目通常把配置拆成三层：数据集配置（根目录、各划分路径、类别数与类别名）、模型配置（结构选择与预训练权重来源）、训练超参数（epochs、batch、imgsz、学习率、增强强度、优化器等）。Ultralytics 风格的命令行接口把这三类参数合并到同一条命令里，并支持用一个 YAML 覆盖默认超参数，因此“默认值到底是多少”必须从固定版本的文档而不是记忆中获得。

# 命令行：显式写出关键参数，便于记录
# 具体选项与默认值请以所用版本的官方文档为准
yolo train model=yolo11n.pt data=dataset.yaml epochs=100 imgsz=640 batch=16 device=0

# Python API：把配置写成可版本化的字典
from ultralytics import YOLO
model = YOLO("yolo11n.pt")
model.train(data="dataset.yaml", epochs=100, imgsz=640, batch=16, seed=0, amp=True)

无论用哪种入口，实验目录里都应保留一份生效后的完整配置（而不是只保留命令行片段），否则无法回答“这个权重是用什么参数训出来的”。

3. 循环里还有哪些会坏掉的细节

数据加载常是第一个瓶颈。GPU 利用率长期低于 50% 时，先怀疑输入管道：增大 workers、确认数据存放在快速存储上、避免在主进程里做重复解码。但 workers 也不是越大越好，进程过多会互相争抢内存带宽与 CPU 核。 混合精度（AMP）用半精度计算降低显存与带宽，但需要损失缩放来避免梯度下溢；某些算子在不支持半精度时会自动回退，具体行为依框架与硬件而定。 EMA（指数滑动平均）维护一份参数平均副本用于验证与导出，它与原始参数不是一回事，“best.pt”到底指 EMA 权重还是原始权重必须确认。 验证与检查点节奏同样是超参数：验证过频拖慢训练，过疏则错过最优区间；保存 last 与 best 两种权重时，“best”的判据（哪个指标、在哪个划分上）必须与报告口径一致。

还有一个容易被忽略的细节是增强的随机性：如果增强管线使用全局随机状态，而数据加载又是多进程并行的，那么每个 epoch 看到的样本顺序与变换都会与单进程情形不同。要真正做到可复现，必须控制这一层的随机种子，并接受某些算子在不同硬件上仍可能有微小数值差异。

4. 有效批大小与学习率缩放

显示在命令里的 batch 往往只是单卡批大小。当使用多张卡或梯度累积时，真正影响优化行为的是每次参数更新所看到的样本数，即有效批大小：

Beff=b·N·k

其中 b 为每卡批大小，N 为设备数，k 为梯度累积步数。常见做法是当有效批大小从 B0 变为 Beff 时，把初始学习率按比例缩放，并配合预热：

η=η0·BeffB0

这是经验性的线性缩放关系，不是定理：加大批后还需要同步调整预热与权重衰减，且往往需要重新验证。下面用固定 4 张卡、基准 16 与基准学习率 0.01 演示：

5. 监控与排障：先看数据，再看超参

监控不是只看一个总 loss，而是把各分项分开：框回归、分类与分布/回归项的趋势分别记录，同时记录每个 epoch 的验证指标。典型的过拟合信号是训练损失持续下降而验证指标停滞或上升；典型的不稳定信号是损失突现 NaN 或大幅震荡。

遇到 NaN 或发散时，排查顺序建议是：先确认输入不含非法坐标、极端尺寸或空标注异常；再检查学习率是否过大、预热是否充足；然后看 AMP 的损失缩放是否稳定。更换模型结构或“堆调参”往往不是第一步。

恢复训练有明确语义：从上次的检查点继续时，需同时恢复优化器状态、学习率调度器与 EMA；并且 epochs 通常表示总轮数而不是“再训多少轮”。在恢复时更换数据集或类别定义会使已有状态与新任务不匹配，属于另一个实验。

多卡训练下，每个进程各自持有数据加载器，随机种子需按 rank 区分，否则多个进程可能采样到相同数据；有效批大小按上文公式计算。分布式训练往往还伴随非确定性算子与通信顺序，完全逐位可复现比单卡更难，报告时应说明这一边界。

6. 一手来源与复核边界

  1. Ultralytics 训练文档：核对训练参数、默认超参数文件与恢复训练的语义。
  2. PyTorch 自动混合精度（AMP）文档：核对损失缩放与算子回退的行为。
  3. PyTorch 可复现性说明：核对种子、非确定性算子与硬件差异导致的复现边界。
  4. Accurate, Large Minibatch SGD（Goyal et al., 2017）：核对学习率线性缩放与预热的原始讨论。
  5. PyTorch 分布式通信包文档：核对 DDP 的采样与通信行为。

本文不给出任何具体训练超参数“最优值”；表格式的“推荐范围”未经实验支撑的均已删除。文中学习率缩放与有效批大小为可推导的约定与教学示例，实际项目需在自有数据上验证并记录完整配置。
