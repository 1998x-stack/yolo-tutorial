MODEL FAMILIES / ATTENTION ／ CHAPTER 18

YOLO11 与 YOLOv12：卷积—注意力的真实取舍

以 Ultralytics 的 YOLO11 文档和 YOLOv12 论文为不同证据源，解释 C3k2/C2PSA、注意力计算预算以及为何 AP、延迟不能脱离部署协议。

1. 先厘清命名：YOLO11 和 YOLOv12 并非同一条发布链

YOLO11 是 Ultralytics 的模型家族，官方文档覆盖检测、分割、姿态、分类等任务；YOLOv12 则是学术论文提出的 Attention-Centric 实时目标检测结构。名称相近不代表作者、权重格式、训练参数或许可证相同。

比较“代际进步”时不能只看版本号，因为 YOLO 家族同时包含公司维护的软件分支和不同研究团队提出的论文模型。请把模型名称、来源、具体权重、commit、推理后端都记入实验报告。

2. YOLO11：局部卷积提取与选择性注意力

Ultralytics 架构说明中，YOLO11 相对 YOLOv8 使用 C3k2 和 C2PSA 等结构。C3k2 在保留局部卷积优点的同时，调整高层模块中的 Bottleneck 组合；C2PSA 在选定位置引入注意力，使网络不仅处理局部纹理，还能利用较宽的空间依赖。

“加入注意力”不自动意味着所有层都运行完整全局自注意力。模块放置位置、通道分组、输入特征图尺寸和后端算子融合都会影响性能。相同参数数目的两套网络还可能因访存与算子调度不同产生完全不同的延迟。

3. YOLOv12：为什么重新把注意力放在中心位置？

YOLOv12 的论文研究如何在维持实时检测目标的同时，更充分利用注意力建模能力。传统全局注意力在 N 个 token 上形成 N×N 关系，理论注意力分数矩阵具有二次规模；卷积更具局部性、硬件实现成熟，但不直接建立所有远距离位置关系。

论文提出区域化/效率导向的注意力设计与卷积组合，使注意力可应用于实时检测器。这不等于“YOLOv12 把所有卷积都换成 Transformer”，也不意味着任意 GPU/CPU/NPU 都能得到同一速度排序。

4. 用可调数字理解注意力矩阵开销

以下不模拟 YOLOv12 的真实算子，而只比较全局注意力关系数 N²和“把 token 划分为大小为 W 的不重叠区域”时约 N·W 的关系数。忽略 Q/K/V 投影、通道维、卷积、张量搬运与窗口边界，因此结果仅用于解释尺度，不能当作实际 FLOPs 或速度提升。

Cglobal∝N2,Cregion∝N·W

固定 N=256 个 token，拖动每个区域的 token 数 W（不代表真实模型计算量）。

5. 从论文 AP 到工程效能还差哪些量？

对照同一 COCO val2017、640 之类的输入尺寸、验证脚本、模型规模、batch=1 与否、是否包含 NMS，区分作者给出的 benchmark 与自己的复现。进一步记录设备型号、驱动、推理后端、FP16/INT8、warm-up 次数、p50/p95 延迟、峰值显存与吞吐；跨硬件 FPS 排行没有解释力。

尤其对注意力模型，理论 FLOPs 少不代表端到端延迟小：内存布局转换、软最大值归一化、kernel 发射成本和后端融合能力同样重要。不能用某个论文表格无条件宣称“注意力比卷积更快”。

6. 如何选用模型

若目标是学习架构，先在同一数据集和同一输出尺度理解 C3k2、C2PSA 与区域注意力之间的表示差异；若目标是边缘部署，先选择确实支持目标硬件算子的 checkpoint，再比较包含预处理、前向与后处理的整条链路。研究对象必须确定到权重和实现版本，而非模糊的 YOLO 代际名称。

一手来源与复核边界

  1. Ultralytics YOLO11 官方文档。用于核查对应机制和版本范围；不把来源中的性能值解释为本页实验结果。
  2. Ultralytics 架构对照。用于核查对应机制和版本范围；不把来源中的性能值解释为本页实验结果。
  3. YOLOv12 原始论文（NeurIPS 2025）。用于核查对应机制和版本范围；不把来源中的性能值解释为本页实验结果。

读者可通过对应论文或项目文档进一步复核具体架构。文中手算数字和交互均是明确的教学示例；没有运行权重训练、推理 AP benchmark 或声称复现任何论文速度表。
