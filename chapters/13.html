MULTISCALE / PREDICTION ／ CHAPTER 13

Neck 与 Head：特征怎样变成可训练的目标预测

Neck 负责不同尺度的特征交互，Head 把融合特征映射到分类与边界框输出，而正样本分配通常属于训练逻辑。借助 SPPF、PAN、解耦头与 TaskAlignedAssigner 拆开三种责任。

1. 三个名字对应不同的数据流边界

目标检测网络中，Backbone 产生 C3/C4/C5 等多层视觉特征；Neck 用上采样、下采样、卷积、池化或跨层连接增强特征；Head 把融合后的张量解码前的输出映射为位置、类别和置信度。最后，由训练侧的 label assignment 为候选位置定义监督，或由推理侧的解码/NMS 把原始输出转换为框。它们可以被实现放在相邻 Python 类中，但语义责任不应混在一起。

以一个输入尺寸为 640×640、三层特征 strides=(8,16,32) 的探测器为例，Neck 可能输出形状 (B,256,80,80), (B,512,40,40), (B,1024,20,20)；Head 再根据具体版本选择每格几个锚框、类别数 C、anchor-free 还是 anchor-based 参数化。示例中的通道数不是任何标准 YOLO 版本的强制值，必须结合模型配置。

2. SPP 与 SPPF：为何三次 5×5 池化能获得 5、9、13 的感受野

Spatial Pyramid Pooling（SPP） 在高层特征图上使用多个不同大小的池化窗口，使局部特征携带多范围上下文。YOLOv4 常见 SPP 模块并行最大池化核 5×5、9×9、13×13；池化操作使用 stride=1 与适当 padding，以保持空间维度不变，最后在通道维拼接。

SPPF（Spatial Pyramid Pooling Fast） 是 YOLOv5 v6.x 结构中的近似相同目的但不同计算实现：使用同一个 5×5、stride 1 的最大池化算子串行三次，依次得到 5、9、13 的有效感受野，把原始输入与三次结果拼接。对于常规最大池化、同一 padding 语义，串行两次 5×5 与单次 9×9 的最大值等价，串行三次对应 13×13。实际性能还要看框架的 pooling kernel 优化，不能因此断言所有硬件都快多少倍。

rn=1+4n,n=1,2,3
python -m labs.neck_head_contract
# 对 7x7 的确定性矩阵，逐像素检查：
# pool5(pool5(x)) == pool9(x)
# pool5(pool5(pool5(x))) == pool13(x)
# 同时验证多头分类/框输出的形状。

池化等价与张量输出检查器 不依赖 NumPy/PyTorch，利用 Python 列表对每个位置求局部最大值；它不能代替真实 SPPF 模块中的卷积和批归一化。

3. PAN 式特征融合和 FPN 是相同网络吗？

FPN 将深层语义通过自顶向下路径传递到高分辨率特征，PANet 再引入自底向上的路径增强，使低层位置信息能更快抵达高层。YOLOv4/YOLOv5 中常见的 PAN-style Neck 借鉴了双向流，但与原始实例分割 PANet 的所有组件并不完全相同。另一个易错点是融合算子：FPN 原论文经典方案采用投影后相加，许多 YOLO 配置采用Concat 后卷积；两者不共享同一输出通道规则。

融合方式输入张量输出约束典型设计考虑
AddH×W×C 和 H×W×CH×W×C需先投影到相同通道
ConcatH×W×C₁ 和 H×W×C₂H×W×(C₁+C₂)保留来源维度但增大通道
Downsample+Concat先使 H/W 对齐通道叠加PAN 路径中的回传

特征图在拼接前必须具有相同 Batch、H、W；不同 padding、奇数输入尺寸、stride 设置可能导致 1 像素偏差。不要让框架自动广播掩盖架构错误，而应为每一个关键融合边界编写 shape 断言。

4. 解耦检测头：为什么分类与定位分开

分类分支需要区分类别相关的外观模式；定位分支要对边缘与框几何保持敏感。耦合头用同一套卷积变换直接产生多种输出，可能形成优化冲突。YOLOX 等工作采用解耦头，让共享输入特征先经过不同卷积分支再预测类别与回归；是否有 objectness 独立分支取决于版本。

它不是“每种输出一个独立 Backbone”，而通常只是在 Head 的尾部拆分轻量卷积分支。若 anchor-based 且每格 A 个参考框，可能输出 A×4 定位通道、A×1 objectness 与 A×C 分类通道；anchor-free 的距离分布回归还可能使用 4×reg_max 个通道。一定要从版本的实际 YAML、Head 源码和 loss 定义推导形状，不能凭一个“Decoupled Head”的名字猜。

D=A(4+1+C)

这个公式适用于有独立 objectness 输出的经典 anchor-based YOLO 检测头，不适用于所有 anchor-free/DFL 或 NMS-free 变体。拆分分支并不会自动改变预测量的定义。

5. TaskAlignedAssigner 不是 Neck，也不是推理阶段的新层

训练检测器需要决定哪个候选位置负责哪一个真值框。只用 IoU 最大的候选可能有好的定位但错误类别；只看分类分数可能选择定位很差的位置。TOOD 提出的 Task Alignment Learning 让正样本选择同时参考分类质量与定位质量，后续部分 YOLO 实现将其发展为 TaskAlignedAssigner 类的匹配器。

m=sαIoUβ

其中 s 是当前预测与目标类别对应的质量分数，IoU 是预测框与目标的重叠，α、β 为可配置指数。实际实现还需要空间内约束、top-k 筛选、冲突处理和目标分配权重；这一简式只解释直觉，不是完整 TOOD/Ultralytics 匹配代码。在推理阶段没有真值框，因此不会运行依赖 GT 的这个分配器。

辅助训练头也应区分：部分模型训练时使用额外分支监督主干梯度，在部署时去除辅助输出。与之相对，NMS-Free 家族在训练分配和推理输出上另有机制，不等于所有“解耦头”都自动可以删去 NMS。

6. 工程验收：哪些错误肉眼难以发现

风险验证方法可定位问题
SPPF 顺序/核错误对小张量与直接 9/13 池化逐元素对照池化尺寸、padding、串行次数
Neck 空间不对齐断言 Concat 的高宽相等stride、up/downsample、奇数输入
Head 通道错误按 C/A/回归模式推导每尺度通道类别数、锚框数或 DFL 输出误配
训练/推理职责混合推理模型检查无 GT 匹配依赖不必要输出和错误后处理

质量比较应将相同的骨干、输入分辨率、训练策略与评估协议固定，然后评估只替换 Neck 或 Head 的影响。一个分支多了卷积层，可能改善 AP，也可能增加推理延迟和显存；不能仅凭拓扑更复杂来宣称它更强。
