ENGINEERING ／ CHAPTER 06

YOLOv3 工程实战：从标注到可复核推理

把检测训练视为一条有明确数据契约的工程流水线：检查标注、配置三个预测头、分离训练与验证、记录实验，再将候选框解码为可检验的最终检测。

1. 一个检测实验由六个可验证的环节组成

YOLOv3 是在三个空间尺度上预测边界框与类别的单阶段检测器。模型能否在自有数据上工作，不仅取决于 Darknet-53 的网络结构，还取决于标签坐标、类别编号、配置文件、输入变换和评估协议之间是否一致。一个环节出错，损失曲线可能继续下降，最终检测却仍然失败。

以“检测两类工业零件”为贯穿示例：类别 0 表示 bolt，类别 1 表示 nut，输入分辨率设为 416×416。这些设置仅用于演示配置关系，不构成任何准确率或训练速度的承诺。

2. 标签契约：五列数字如何映射回原图

常见的 Darknet YOLO 标注文件为每张图像配一个同名 .txt 文件，逐行写入 class_id cx cy w h。其中中心坐标与宽高均按原图尺寸归一化，类别从 0 开始编号；检测框不能越界、尺寸必须大于 0。训练实现会处理缩放和增广，但标签源必须以数据集约定的坐标为准。

# images/001.jpg : 假设原始分辨率是 640×480
# labels/001.txt : 一条合法标注
0 0.500000 0.500000 0.250000 0.500000

# 像素框对应：
# center = (320, 240), width = 160, height = 240
# x1=240, y1=120, x2=400, y2=360

这五列不是 x1 y1 x2 y2，也不是 COCO 格式的 x_min y_min width height。如果混用两种格式，模型训练可能仍会运行，但框会系统性偏移。空标注文件可以代表经过核实的纯背景图；缺失标注、错误的类别 ID 或故意丢掉难样本不能当成“背景增强”。

检查应满足的约束常见错误
类别整数，0 到 C−1把类别从 1 开始编号
几何0≤cx,cy≤1，w,h>0，框在图像内像素值被当作归一化数值
数据划分按相机、设备、视频片段或拍摄批次隔离近重复图同一视频相邻帧被拆入训练和测试
验证集不参与训练、锚框优化或超参选择之外的测试报告反复用测试集调阈值或挑模型

3. 三个预测头：filters、classes 与 mask 必须一致

标准 YOLOv3 对 COCO 使用三尺度预测。在 416×416 输入下，输出特征图约为 13×13、26×26、52×52；每个位置分配三个锚框。若改为 C=2 类，则三个检测头前的最后一个卷积层都必须有 3×(5+2)=21 个 filters；对应的 [yolo] 层都必须设为 classes=2，且与该头的三个 mask 索引一致。

Fhead=A×(5+C)=3×7=21 
# 三组都需修改：卷积层的 filters=21 与其后的 [yolo] classes=2
# 示意：完整 cfg 还有许多其他卷积、route、shortcut 等层
[convolutional]
filters=21
size=1
stride=1
pad=1
activation=linear
[yolo]
mask=6,7,8
anchors=10,13, 16,30, 33,23, 30,61, 62,45, 59,119, 116,90, 156,198, 373,326
classes=2

锚框表中的顺序很重要：mask=6,7,8 引用列表中的第 7–9 个先验。若更换锚框，需要同时检查全部三个预测层的锚框列表与 mask 映射。此处简化段落不是完整 Darknet cfg，不能直接拿它作为可训练网络配置。

# 下载并修改自己的完整 yolov3 cfg 后，对其进行无依赖配置审计
python -m labs.darknet_cfg_audit path/to/yolov3-custom.cfg --classes 2

# 通过时报告三组检测头的 mask/classes/filters 一致性
# 若仅修改一个 [yolo] 的 classes 或某一个 filters，则检测会失败

本仓库的 配置检查脚本 只验证基础结构约束，不会替代 Darknet 自身的解析、张量形状测试和完整模型训练。标准 YOLOv3 与 tiny YOLOv3 的预测头数量不同，这个检查器专门面向完整三头版本。

4. 训练：从可复现基线开始，而不是堆叠技巧

训练前记录仓库 commit、操作系统、CUDA/驱动版本、权重来源、类别表、划分文件、训练参数和随机种子。使用 AlexeyAB/darknet 的历史 YOLOv3 工作流时，训练数据清单是一行一个图像路径，obj.data 保存类别数、训练/验证清单、类别名文件和权重备份路径。

# data/obj.data（路径根据实际 Darknet 工作目录修改）
classes = 2
train = data/train.txt
valid = data/valid.txt
names = data/obj.names
backup = backup/

# data/obj.names
bolt
nut

# 完成 Darknet 编译、cfg 修改和预训练权重准备后：
./darknet detector train data/obj.data cfg/yolov3-custom.cfg darknet53.conv.74 -map

这里的 darknet53.conv.74 是常见的 Darknet-53 卷积预训练权重文件名；其来源与版本应由实验者核验。完整构建和训练参数以所固定的 Darknet 仓库 commit 文档为准。特别要避免将 YOLOv5/Ultralytics 命令行参数照搬到 Darknet cfg，二者不是同一种训练接口。

建议先完成极小样本的过拟合烟雾测试：选取少量确认无误的图像，观察模型能否在训练集上学会准确框出它们。若连这一步都失败，优先检查标注和模型配置，而不是盲目延长 epoch。正式训练时再记录验证集 AP、召回、误检与不同尺度目标表现，不能只看训练 loss。

5. 推理：解码、分数与逐类别 NMS

YOLOv3 在每个网格位置预测锚框中心偏移、宽高、objectness 和独立类别分数。三个尺度的候选框汇总之后，应按类别形成检测分数，再筛选阈值和应用非极大值抑制（NMS），将指向同一目标的重复预测减到合理数量。

本仓库提供 OpenCV DNN 推理示例，从原始 Darknet cfg/weights 读取 YOLOv3，在 CPU 上运行并执行逐类别 NMS。它显式计算 objectness × class_probability，而不是把类别分数误当作最终检测置信度。

python -m pip install -r labs/requirements-inference.txt
python -m labs.yolov3_opencv \
  --cfg path/to/yolov3.cfg --weights path/to/yolov3.weights \
  --names path/to/coco.names --image path/to/image.jpg \
  --size 416 --score 0.25 --nms 0.45 --out predictions.jpg

推理演示使用 OpenCV 的直接缩放（不做 letterbox），并用原图宽高分别反算坐标。训练数据若采用 letterbox 管线，必须用对应的 padding 与缩放比例进行逆变换，不能把两种预处理策略混用。权重文件较大，仓库不提供第三方权重或样例数据的副本。

6. 面对“训练正常、结果很差”怎样定位原因？

现象首要排查点可执行的验证
预测框整体偏移xywh 格式、letterbox 逆变换、原图宽高将 20 个标签画回原图并人工核对
分类全部偏到某一类类别 ID、names 顺序、三个 classes逐类统计频率并检查 cfg 与字典
小目标召回低标注分辨率、尺度匹配、锚框覆盖按面积分组汇报 AP/Recall
训练 loss 降、验证 AP 不升过拟合、数据泄漏或域差异同时看 train/valid 的同口径指标与失败样例
NMS 后目标消失阈值过高、全类别混合 NMS保存 NMS 前后候选明细，逐类别比较

性能报告至少应含：数据集版本与划分、IoU 阈值或 COCO AP 协议、模型输入分辨率、权重版本、推理硬件、是否包含预处理与后处理时延。只提供“训练 100 epoch 达到 90% mAP”无法做可核验的横向比较。
